# 项目边界与真实性说明

## 1. 项目来源

本项目基于实习期间接触的常见接入网故障排查思路进行个人学习实现。公开版本仅保留通用流程和完全模拟的数据，不包含公司内部系统、真实网络标识、原始资料或生产配置。

## 2. 个人工程原型部分

以下功能基于实习流程使用脱敏/模拟数据实现，属于个人学习与求职作品，不代表运营商生产系统已有能力：

- LangGraph 状态工作流；
- 本地模拟资源台账；
- 命令输出解析器；
- 规则诊断引擎；
- LangChain + Ollama Embedding + FAISS 本地知识检索；
- 只读 MCP Server；
- FastAPI、Web UI、Checkpoint、审计和报告归档；
- OpenAI-compatible / 本地 Hugging Face 报告整理后端；
- FP16、INT8、INT4 本地模型加载与量化 benchmark 工具。

如果简历需要描述时间关系，推荐使用“结合实习期间接触的排障流程，后续使用脱敏模拟数据搭建/完善个人原型”，不要写成生产系统部署成果。

## 3. 严禁夸大的表述

不得描述为：

- 已部署至运营商生产环境；
- 已接入真实 MSE、资源系统、堡垒机或交换机；
- 自动完成故障修复或网络配置变更；
- 使用真实客户工单训练出高准确率模型；
- 量化后获得固定百分比的加速/显存下降（除非在自己的硬件上实际测量并保留原始结果）；
- 为电信节省了未经真实测量的工时或成本。

## 4. 面试推荐回答

> 项目没有接入运营商生产环境。它基于我实习中真实接触的 IP—资源设备—交换机端口—MAC/VLAN 核查流程，使用脱敏和模拟数据复现。我把关键网络状态写成确定性解析与规则，用 LangGraph 管理流程、人工审批和失败恢复，用 MCP 暴露只读工具，并通过 langchain-mcp-adapters 验证 MCP 工具可转换为 LangChain Tools；RAG 和大模型只负责知识检索和已有证据的报告整理。另外我增加了本地 Hugging Face 模型后端，用 FP16、INT8、INT4 做推理资源对比，量化结果以实际 benchmark 为准。
