# 文档出处与构造原则

**约束：不把构造的数据说成真实工单。** 原始电信资料支持的是业务核查方法与典型故障现象，通常没有可公开的逐工单 CLI、IP、最终维修记录。本项目使用的脱敏 IP/MAC/VLAN 均为模拟示意数据。

## 严格来源

1. 用户上传的《网络运维系统及接入交换机故障定位工作.pdf》：
   - 第1页：故障信息与典型现象（网络不通、OA/互联网异常、地址调整、间歇性）；
   - 第2页：IP 经全局查询脚本定位接入号；
   - 第3页：MSE 按接入号定位登记设备/端口，资源信息不代替实时状态；
   - 第4页：`display interface`、接口 UP/DOWN 和错误统计；
   - 第5页：MAC 学习、接口 UP 无目标 MAC、老化及端口核查；
   - 第6页：端口 VLAN、Access/Trunk、地址调整后核查；
   - 第7页：MSE 与设备状态双向核验、接口 DOWN 处理；
   - 第8页：UP 无 MAC、UP 有 MAC 业务不通、ipconfig/ping/nslookup/tracert；
   - 第9页：资源与实际接入关系冲突、完整定位流程。
2. 用户上传《文件.pdf》（DCN 生产网与 OA 办公网隔离通知），第1–3页：最小权限/隔离、地址整改与配置核验要求。**不把通知中的企业专有网段和策略细节写入可复用样例。**
3. 原项目 `knowledge/sanitized/` 七份脱敏知识文件作为 RAG Gold 的目标章节，按文件名与实际小节标注。

## 两类数据需严格分开

- `data/rag_eval/queries_150.json`：**原项目历史受控模拟 Query**，保留它和既有历史评测结果作为简历原始证据，不声称逐条来自真实电信工单。
- `data/rag_eval/queries_document_grounded.json`：**新增 34 条资料约束的排障问题**，每条包含原始来源文件、页码、章节、支持点、Query 和 Gold 知识章节。若不能从原文支持，不纳入数据集。

## 案例性质

- `data/sample_requests/*.json` 是已有的模拟 CLI，数据字段为演示用，不是运营商生产设备采集结果。
- `tests/test_hardening_network.py` 中的负样本（无法解析、多接口串读、过期证据）是**工程安全边界测试**，并不暗示这些故障真实发生在电信现场。
- 如果后续要声称“真实故障诊断准确率”，必须取得合法脱敏工单、真实采集证据和独立复核标签，当前没有。
