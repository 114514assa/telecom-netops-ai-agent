# 接入网故障定位流程

## 1. 故障信息收集

接到终端网络异常时，先记录必要信息：

- 模拟终端 IP，例如 `10.20.30.15`
- 用户所在逻辑区域
- 故障发生时间
- 故障现象
- 是否近期调整过地址或接入位置
- 是否能够访问内部办公系统
- 是否能够访问互联网
- 是否为间歇性故障

常见现象可先分为：

- 网络完全不通
- 内部业务异常
- 互联网访问异常
- 地址调整后异常
- 终端接入位置不明确
- 间歇性丢包或断连

## 2. 从 IP 定位接入资源

典型只读定位链路：

终端 IP  
→ 查询接入关系  
→ 获取模拟接入标识  
→ 查询资源记录  
→ 获取登记设备、端口、区域和 VLAN  
→ 与当前设备侧证据交叉核对

在 Agent 原型中，资源查询应来自模拟或脱敏后的资源表，不直接访问真实生产网管系统。

示例：

| 字段 | 模拟值 |
|---|---|
| IP | 10.20.30.15 |
| 接入标识 | ACC-SIM-001 |
| 登记设备 | SW-SIM-01 |
| 登记端口 | GE0/0/15 |
| 目标 VLAN | 200 |

## 3. 资源记录与实时证据交叉核验

资源记录反映“理论接入关系”，设备查询结果反映“当前实际状态”。

重点比对：

- 登记设备是否与当前核查设备一致
- 登记端口是否与实际学习端口一致
- 接口是否 UP
- 是否学习到目标 MAC
- MAC 所属 VLAN 是否与目标 VLAN 一致
- 资源记录是否可能滞后

不能仅凭某一个字段直接认定故障，应结合多项证据判断。

## 4. 常见故障判断

### 4.1 接口 DOWN

证据：

- 目标端口 Physical/Protocol 状态为 DOWN
- 通常没有目标终端 MAC

优先排查方向：

- 终端是否在线
- 网卡状态
- 网线与物理连接
- 中间链路
- 实际接入端口是否正确

接口 DOWN 不应直接等同于“交换机故障”。

### 4.2 接口 UP，但没有目标 MAC

证据：

- 接口状态正常
- MAC 表中未发现目标终端

继续核查：

- 终端是否产生网络流量
- 网卡是否启用
- 终端 MAC 是否发生变化
- 查询端口是否正确
- 接口 VLAN 是否与目标网络一致
- 动态 MAC 表项是否已老化

### 4.3 接口 UP，存在 MAC，但业务仍异常

说明二层基本连通不一定等于业务正常。

继续检查：

- 终端 IP 地址
- 子网掩码
- 默认网关
- DNS
- VLAN 是否正确
- 上层路由或访问策略
- 目标业务系统状态

### 4.4 VLAN 不一致

示例：

- 资源登记目标 VLAN：200
- 当前 MAC 学习 VLAN：210

此时可判断“设备侧 VLAN 证据与资源登记不一致”，但不由 Agent 自动修改配置。

处理方式：

- 记录差异
- 检查资源记录是否准确
- 检查实际接入位置
- 将结果交由授权维护人员确认

### 4.5 资源端口不一致

示例：

- 登记端口：GE0/0/15
- 当前目标 MAC 学习端口：GE0/0/18

可能表示：

- 终端位置发生变化
- 资源记录未更新
- 查询对象错误
- 存在接入关系偏差

应保存证据并人工复核，不直接更新生产资源数据。

### 4.6 接入侧证据正常但业务异常

若满足：

- 设备一致
- 端口一致
- Interface 正常
- MAC 正常
- VLAN 正常

但业务仍不可访问，则故障范围可能已超出接入侧，应继续核查：

- DNS
- 上层路由
- 访问策略
- 业务系统
- 其他上层网络路径

## 5. 推荐诊断顺序

1. 核对资源关系
2. 核对当前设备
3. 核对当前端口
4. 查看 Interface 状态
5. 查看 MAC 学习
6. 核对 VLAN
7. 必要时查看 ARP
8. 检查终端 IP / 网关 / DNS
9. 判断是否需要转向上层网络或业务系统
10. 记录证据并人工确认

## 6. Agent 输出边界

Agent 可以输出：

- 当前已确认事实
- 证据之间的一致性或差异
- 初步故障分类
- 建议继续核查的方向
- 知识库参考依据

Agent 不应：

- 自动修改 VLAN
- 自动 shutdown/no shutdown
- 自动重启设备
- 自动修改资源台账
- 将缺少证据的推测写成已确认事实
