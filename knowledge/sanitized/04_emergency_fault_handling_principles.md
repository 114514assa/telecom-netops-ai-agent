# 网络故障处理与应急原则

## 1. 故障处理基本原则

故障处理应优先保证业务影响可控，并遵循：

1. 先明确故障现象和影响范围
2. 收集证据，不凭单一现象直接下结论
3. 根据证据缩小故障范围
4. 形成处理或升级计划
5. 高风险操作必须经过授权
6. 每一步处理后观察结果
7. 故障恢复后进行复测并记录

Agent 原型只负责前四步中的辅助分析、证据组织和知识检索，不自动执行生产变更。

## 2. 标准故障定位方法

### 第一步：定义故障

记录：

- 什么业务异常
- 哪些用户或设备受影响
- 是否全部中断
- 是否间歇发生
- 故障发生时间

### 第二步：收集症状和证据

可收集：

- Interface 状态
- 流量与错误计数
- MAC
- ARP
- VLAN
- 资源登记信息
- 终端 IP / 网关 / DNS
- 上层访问结果

### 第三步：缩小故障范围

可按层次分类：

- 终端侧
- 物理链路
- 二层接入
- VLAN
- 三层地址或网关
- 上层路由
- DNS
- 业务系统
- 资源数据不一致

### 第四步：形成下一步建议

建议应以“查询、核对、补充证据、升级人工处理”为主。

## 3. 常见设备和链路问题

常见问题类型包括：

- 设备掉电
- 端口异常
- 线缆断开或质量下降
- 接口松动或连接错误
- 网络模块异常
- 软件运行异常
- 链路拥塞
- 丢包或时延升高

对于 Agent 来说，上述内容只能作为可能原因库，只有获得对应证据后才能提高置信度。

## 4. 时延和丢包问题

若出现：

- 到默认网关时延明显升高
- Ping 持续丢包
- Interface 错误计数增加
- 历史流量存在持续拥塞

可将问题归入：

> 链路质量或容量异常，需要继续人工核查。

不得仅凭一次 Ping 丢包直接断定设备故障。

## 5. 故障升级

以下情况建议升级正式维护人员：

- 资源数据与实际设备证据冲突
- 需要执行生产配置修改
- 需要更换硬件
- 影响范围扩大
- 需要重启或切换设备
- 上层网络路径无法通过现有只读证据确认

## 6. 复测与闭环

问题处理后应复测：

- Interface 是否稳定
- MAC 是否正常学习
- VLAN 是否符合规划
- ARP 是否恢复
- 网关是否可达
- DNS 是否正常
- 内部业务是否恢复
- 互联网或目标业务是否恢复

同时记录：

- 原始现象
- 已确认原因
- 关键证据
- 处理人员
- 复测结果
- 是否闭环
