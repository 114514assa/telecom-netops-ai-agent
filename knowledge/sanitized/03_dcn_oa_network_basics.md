# DCN 与 OA 网络基础

## 1. 网络用途区分

### DCN 生产网络

典型用途：

- 网络设备管理
- 网络监控
- 运维支撑
- 生产维护系统
- 网络管理平台

特点：

- 面向生产运维
- 安全要求较高
- 不应作为普通办公和互联网访问网络长期混用

### OA 办公网

典型用途：

- 日常办公
- 内部审批
- 协同系统
- 办公云终端
- 互联网访问

终端所属网络应结合业务用途、地址规划和 VLAN 共同判断。

## 2. 地址与 VLAN 一致性

终端网络正常通常需要以下信息彼此匹配：

- IP 地址
- 子网掩码
- 默认网关
- DNS
- 接入 VLAN
- 实际业务用途

地址调整后出现业务异常时，不能只检查 IP 是否修改成功，还应核对：

- 网关是否属于目标网络
- DNS 是否正确
- 实际接入 VLAN 是否已与目标网络一致
- 终端是否仍依赖原网络中的固定地址或访问策略

## 3. 终端地址整改的核查思路

整改前：

1. 确认终端业务用途
2. 确认是否存在固定 IP 依赖
3. 确认是否存在白名单或特殊业务绑定
4. 记录当前网络配置
5. 确认目标网络规划

整改后：

1. 查看 IP 地址
2. 查看子网掩码
3. 查看默认网关
4. 查看 DNS
5. 验证网关连通
6. 验证内部办公业务
7. 验证互联网访问
8. 验证域名解析
9. 记录异常并复测

## 4. 终端接入定位

通用只读流程：

终端 IP  
→ IP/MAC 关系  
→ 目标 MAC  
→ MAC 所在端口  
→ 当前接口 VLAN  
→ 判断网络归属

示例模拟数据：

| 项目 | 值 |
|---|---|
| IP | 10.20.30.15 |
| MAC | 00:11:22:33:44:15 |
| 设备 | SW-SIM-01 |
| 端口 | GE0/0/15 |
| VLAN | 200 |
| 网络用途 | OA-SIM |

## 5. 风险判断原则

不能仅根据地址前缀判断是否应该迁移或调整网络。

还需结合：

- 用户/终端实际用途
- 是否承担生产维护
- 是否访问网管系统
- 是否存在固定地址依赖
- 是否有特殊业务访问需求

信息不足时应标记“待确认”，而不是由 Agent 自动作出生产变更决策。
